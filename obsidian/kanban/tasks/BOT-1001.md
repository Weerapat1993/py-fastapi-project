## BOT-1001: NotebookLM → Discord Q&A Bot

Status: Plan
Priority: Medium
Spec: `docs/superpowers/specs/2026-07-23-notebooklm-discord-bot-design.md`

### Summary
Build standalone Discord bot relays `/ask` questions to fixed Google NotebookLM notebook (via unofficial `notebooklm-py` CLI), reply answer + citations. Stateless per question, single notebook, run local via Docker.

### Context
- Design spec: [2026-07-23-notebooklm-discord-bot-design.md](../../../docs/superpowers/specs/2026-07-23-notebooklm-discord-bot-design.md)
- Implementation plan: [2026-07-23-notebooklm-discord-bot.md](../../../docs/superpowers/plans/2026-07-23-notebooklm-discord-bot.md)
- New standalone repo (not part of `py-fastapi-project`): `/Users/mungmee/Desktop/Project/Python/notebooklm-discord-bot`

### Scope
- In: Discord slash command `/ask`, NotebookLM CLI wrapper, answer/citation formatting, Docker packaging, local auth-refresh scheduling.
- Out: conversation memory, multi-notebook routing, Line OA adapter, VPS hosting.

### Acceptance Criteria
- [ ] Repo scaffolded (`requirements.txt`, `.env.example`, `.gitignore`, `README.md`)
- [ ] `config.py` loads `DISCORD_BOT_TOKEN` / `NOTEBOOKLM_NOTEBOOK_ID`, fails clearly if missing
- [ ] `nlm_client.ask()` wraps the `notebooklm` CLI, typed errors for auth-expired / rate-limited / timeout
- [ ] `formatting.py` chunks long answers under Discord's 2000-char limit, truncates citation list to 1024 chars
- [ ] `/ask` command wired end-to-end: defer → call NotebookLM → reply with embed (answer + "แหล่งอ้างอิง")
- [ ] All error paths reply with the correct Thai message (auth expired / rate limited / timeout / generic)
- [ ] Dockerfile + docker-compose (`restart: unless-stopped`) build and run locally
- [ ] NotebookLM auth-refresh scheduled locally (launchd, every ~15 min)
- [ ] End-to-end manual verification against a real Discord server + real notebook passes (happy path, long-answer chunking, auth-expired path)

### Validation
- Backend: `pytest` + `pytest-asyncio` per task in the linked implementation plan (unit tests before each task's implementation, TDD style)
- Manual: end-to-end check against a real Discord server + real notebook (happy path, long-answer chunking, auth-expired path) — see last acceptance criterion

### Implementation Plan
Full task/step breakdown already lives in the linked plan doc (`docs/superpowers/plans/2026-07-23-notebooklm-discord-bot.md`), written for `subagent-driven-development` / `executing-plans` execution — this ticket does not duplicate it. Summary:

- Context: standalone repo at `/Users/mungmee/Desktop/Project/Python/notebooklm-discord-bot` (outside this repo), Python 3.11+, `discord.py` + `notebooklm-py` CLI via subprocess, no DB/web server/conversation state.
- Planned changes: 8 TDD tasks — repo scaffolding, config loader, NotebookLM CLI wrapper w/ typed errors, answer/citation formatting, `/ask` command wiring, Thai error messages, Docker packaging, local auth-refresh scheduling (launchd) — each gated by tests written first.
- Files likely to change: all in the standalone repo above, not in `py-fastapi-project`.
- Validation commands: `pytest` (with `pytest-asyncio`) per task; final manual E2E pass against a live Discord server + notebook.
- Risks / decisions:
  - `notebooklm-py` relies on personal Google account cookies — outside NotebookLM's ToS; acceptable only for personal/small-group use, do not scale to high query volume.
  - Bot uptime is tied to the local machine (no VPS uptime guarantee).
